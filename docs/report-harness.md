# 报告 Harness

## 当前边界

本模块包含报告证据、独立审查运行控制和显式正式运行装配，旧报告链路保持默认。
生产工厂默认关闭新模式，不能通过客户端字段选用合成角色或测试批准表。
服务端显式设置 `report_harness.enabled=true`，且schema及批准表只读权限验证通过后，
可使用证据/运行数据接口；
`online_enabled` 默认 false；只有同时提供完整业务 manifest、只读发布批准、
有效代码清单及既有预算合同，主应用才可装配在线运行。旧配置缺少此配置组时行为不变。
源码支持这一入口不代表已部署或已通过真实报告质量验收。
合成角色只用于控制流测试，不能证明真实报告质量。

当前开发路径支持人工文字补证、冻结快照和受控的本地知识查询；
计账 transport 已在隔离回环 HTTP 中集成验证；另有须明确授权的隔离真实开发入口和默认关闭的正式业务装配，
未完成的能力明确拒绝，不假装已执行。
候选、审查与发布正文存入专用 PostgreSQL 表，不写旧报告输出目录。
真实质量验收、模型外发、生产迁移和部署均不是运行测试的附带操作。

## 证据与授权

- 会话证据使用独立 GET/PUT `/api/v1/chat-sessions/{session_id}/report-evidence`，
  全量保存带 `expected_revision`；来源、核实状态、冲突和服务端审计字段共同保留。
- 创建 run 时在数据库事务内检查 revision 并冻结文本；之后的证据或草稿修改不会改变旧 run。
  草稿字段未就绪时保存返回警告，创建 run 时无效 JSON Pointer 必须拒绝。
- 所有者可读取 `/api/v1/report-runs/{run_id}/authorization-preview`；
  缺少完整的服务端端点描述或获批知识清单时明确不可批准，不返回密钥或自动探测端点。
- authorize 必须确认快照、端点配置和知识清单三个服务端摘要。
  授权与事实核实状态互相独立，不能由模型写入 approved，也不会增加预算。
- 未初始化正式运行依赖时，公开生产入口的 outbound 返回 `outbound_transport_unavailable`。
  已初始化时，执行仍需逐运行快照授权、当前批准绑定、资源和预算检查。
  隔离开发入口须由代码显式注入开发依赖、许可目录、受控transport及工程导出约束；
  不能由用户API传一个开关启用，也不能使用合成档位冒充真实调用。

## 受控上下文

完整业务接入组件位于 `business_roles.py`、`business_workflow.py` 和
`runtime_factory.py`；工程工厂由开发入口显式注入，正式工厂则由
`production_runtime.py` 在主应用生命周期内只读装配，二者不得混用。
业务工厂要求专家、生成、独立审查、嵌入四类端点及容量证明与许可目录一致，
并强制绑定持久货币合同和资源检查；不复用旧 provider 的隐藏重试。
原专家与报告模板经共享纯渲染函数接入，原句引用由程序转换为唯一字符区间。
控制器强制执行并持久记录事故信息首检，再允许受轮数、条数和查询长度限制的主动检索。

独立审查必须完整读取当前候选全部结构化知识引用。工具按角色保存实际返回的字符区间，
分页覆盖必须连续并闭合全文；仅目录、单页或中间有缺口的区间不算已读。恢复时重核读取记录，
未完成原文阅读不能通过发布检查。原报告模板保留业务输入占位，不再设字数目标或最低段落数；
篇幅按必要事实、推理、引用及不确定性决定。

`business_bootstrap.py` 从既有业务配置装配四角色，检查模型元数据、最高推理等级、
已批准知识内容摘要及既有货币合同；只读启动检查不创建新账本或登记新合同。
`business_server.py` 是独立显式开发启动入口，复用原应用的登录、会话和报告 API，
默认仅监听运行主机的回环地址，始终使用工程导出。它不是正式入口切换开关。
此显式开发入口也向原页面暴露可用能力，避免只能用CLI验证；开发状态与正式批准分离，
不能借此取得正式成功响应或正式下载资格。
配置中的未知请求确认只认可明确列出的正整数 attempt 编号，不把新未知请求自动加入。
现有合同中的预留与累计费用继续占用原实验额度；模型余额不等于允许追加预算。

当公开配置 `/api/v1/app-config` 的 `report_harness.online_enabled` 为 true 时，
原事故页面挂载 `IntegratedReport`，沿用事故表单确认按钮：严格保存成功后才创建快照、
取得当前授权摘要并执行。页面支持补证来源与位置、修改删除、中文进度、历史恢复、
取消、未知请求显式确认和符合发布条件的报告下载，不再要求用户操作工程面板。
代码仍保留旧页面路径；合成浏览器验证不能证明真实报告质量或正式导出资格。
公开配置加载失败时禁止生成，不回退旧接口；服务因资源不足降级时仍保留历史与取消。
未知请求的重试确认仅消费一次，切换运行或状态版本后清空，不沿用到下一份报告。
收费生成、审查和嵌入限定为当前受支持的 OpenRouter 路径，发包时带与预留报价对应的
供应商单价过滤并禁止回退；它限制收费路由，不是输出 token 上限。温度与表达详略
沿用原端点配置并纳入运行摘要，模型不得覆盖。自有嵌入服务仅在已有批准的
`local_token_free` 合同且与专家使用同一基础端点时允许，不因此跳过物理请求记账。
专家响应在进入持久账本前去除可识别的
独立思维字段，仅保留解析后的指导 JSON 与 usage；生成、审查协议 JSON 也清理可识别
思维字段和思考块，正常业务分析及 `completed_checks` 的 `reasoning` 类别保留。
无有效协议 JSON 时显式失败，同时保留实际 usage 结算信息。
角色 `timeout_seconds` 和整轮剩余时间取较小值，覆盖完整物理请求而非单个网络读取阶段。
未指定 token 预算时按已核验的模型容量元数据和默认24次物理请求生成内部预留；
专家使用标称 `max_context_length` 保守预留，不等于实时 `loaded_context_length`，
也不代表已实现基于 tokenizer 的输入容量校验。预留不转换成模型输出截断参数。
显式预算须覆盖配置的全部物理请求次数（按最大角色容量预留），且至少容纳首轮四角色；
不足时启动拒绝。24次是默认值而非固定上限，不静默扩大配置或100元货币额度。
修订已有收费角色合同必须同时匹配当前总合同摘要与旧角色摘要；只追加版本，
旧请求仍绑定原合同，旧费用和未知预留不变，旧客户端不能继续使用已经变更的绑定。
启动方式与必需资源路径见部署说明。单元装配或回环合成测试不代表真实报告质量通过。

完整业务模式可绑定只读共享知识资产摘要，不在每个 run 复制整库；
实际用到的原文仍保存于知识登记与工具轨迹。资产版本变化拒绝继续旧运行。
混合检索复用原排序，嵌入物理请求进入统一 transport；费用未知、授权失败不会
被捕获后静默降级为稀疏结果。控制器执行合同版本3拒绝直接续跑旧合同，
包含语义问题严重度下限规则；不把新判定规则套用到旧运行的恢复过程。

生成和审查各自通过有界角色循环调用 `list_evidence`、`read_evidence`、
`search_knowledge`、`read_knowledge`。工具没有 shell、文件读取、URL 抓取、
修改事实、改变预算或批准发布的能力。知识来自服务端固定注入的原文集合，
不是模型 prepare 返回的新事实；创建运行时固定副本和摘要，配置变更拒绝执行旧运行。

大快照只给目录和必要事实义务，模型须回查原文。目录中的 ID 存在不代表已读；
发布检查分开校验生成者引用来源和审查者实际取得的证据/知识，语义支持仍由审查负责。
每次工具执行前后保存私有检查点；公开事件只包含受控工具名、状态和摘要。
生成者工具历史不会进入审查者上下文。逻辑工具次数上限不能替代物理请求费用账本。

## 审查与修订

审查问题由控制器分配稳定 ID，原始定义及历次回应保留。生成者的可选
`issue_responses` 只能说明修订或提出带来源的争议，不能关闭问题；
后续独立审查必须逐个回应旧的未关闭问题，不能改 ID、降级或悄改闭合条件。
模型误将非明确排版措辞的问题标为 minor 时（包括事实、推理、引用和覆盖），
控制器在写入问题台账前将其提升为
major，按阻断问题进入有界修订；不改失败检查、不自动关闭问题。审查历史同时保存
`raw_review` 原始响应和执行严重度，发布仍要求独立审查闭合与全部检查通过。
五类 `CompletedCheck` 的模型输出协议明确要求证据/知识引用至少一项非空，
包括简洁性检查；模板要求按必要事实和输出边界核对简洁性，不能填无关引用凑数。
结构协议用于提前表达已有校验要求，不能代替服务端来源授权与语义支持审查。
每次候选变更都重新检查五类要求和全部必要事实，清空该轮角色的旧原文访问记录。
候选历史和审查历史分别保存版本、摘要与内容，最终发布只使用最终版本的审查。

最多两轮修订；仍存在重大问题或未通过检查则 `needs_review`，保留候选供查看，
没有人工一键跳过发布。仅排版措辞类 minor 可随报告保留。
新模板位于 `backend/config/report_harness/`，创建 run 时冻结，旧模板不受影响；
没有报告字数目标或最低段落数。合成修订测试不证明真实审查能发现语义错误。

## 物理请求与预算

新链路的 `TransportRoles` 使用固定角色配置和 `BudgetedTransport`，不复用旧 provider
的隐藏重试、端点回退或模型驻留操作。每次 HTTP attempt 先在 PostgreSQL 登记 intent，
发送前原子转为 dispatched；本地发送线性化点之后视为在途，不承诺远端恰好一次。
请求与 run 共用行锁串行检查 fencing 和余额；取消不能被迟到的结果覆盖。

已知 usage 结算后释放未用预留；缺失或无效 usage 保留全部 token 预留并暂停，
超出预留如实计账且停止后续请求。预算视图从账本聚合，迟到结算不修改运行状态、
正文或状态版本。preparing 必须容纳生成与最终独立审查；其他动作保留最终审查容量。
活动时间使用数据库时钟累计，暂停期间不增加。

token 上界必须由服务端经过验证的协议证明提供，包含可计费输入和输出；
当前合成协议证明只适用于测试，不能证明真实模型的 token 上界。
没有经验证价格表时硬货币预算拒绝启动。真实端点、模型、资料与费用仍需独立批准。

## 独立数据库

测试只接受 `REPORT_HARNESS_TEST_DSN`。host 必须为回环地址，数据库名必须以
`safetyraise_harness_test` 开头。禁止读取业务 `.env`，缺少 DSN 是测试错误，不是跳过条件。

`backend/app/report_harness/migrations/001_report_runs.sql` 是显式版本迁移。
测试 fixture 仅在已确认的独立库建立最小旧表契约和新表，并清理自己创建的用户与运行记录；
不删除数据库、不操作已有业务用户或会话、不在生产服务启动时迁移。

## 恢复与关闭

当前运行迁移版本序列为 1、2；版本不匹配拒绝使用新模式，不能降级成忽略持久化的执行。
版本2解除会话到run/补证的删除外键，保留run到账本与事件的RESTRICT约束，
并增加 `session_deletion_barriers`，不能只删除会话而遗留可执行run。

取消在数据库事务内使旧令牌失效、拒绝未发送intent并将dispatched记为未知。
执行任务每250毫秒观察持久屏障，租约心跳仍每5秒更新；
本地关闭不代表能撤销已发送的远端调用。控制SSE断连会持久取消，
清理区屏蔽重复异步取消并等待worker关闭，不能断连后后台继续。

会话删除先在同一事务内建立屏障、撤销run、保留账本，再删除会话行；
事务提交后再清理原有会话文件。读写和历史文件迁移均检查屏障，防止迟到写回复活。
文件清理仅限解析并核验后的当前会话目录及其后代；客户端元数据不能扩大删除范围。
Windows 会话锁使用大小写等价键；屏障同时阻断大小写别名，拒绝复用其他会话目录的ID。
目录组件拒绝尾随点/空格、备用数据流、保留设备名等特殊路径。普通大小写ID保持可用。
这些数据库屏障保证要求迁移版本2；旧模式缺表兼容不具备同等持久删除保证。
无法证明归属的历史外部产物保留，不将会话删除宣传成对所有外部引用的物理清除。
已发布的终态正文不会被删除操作改写，但所有公开读取立即失去权限。
只有匹配原owner/run/request/attempt/token的内部结算可跨越删除屏障，
不能新增请求或恢复正文/发布权限；此结算入口不暴露为API或模型工具。

## 崩溃恢复

服务在新模式启用后每5秒有界扫描过期租约，锁内复核后标记
`suspended/orphaned_process`，不迁移表、不调用模型、不自动继续执行。
普通GET也会本地对账；恢复必须显式提交当前状态版本。
已经取消或发布的终态不可恢复，数据库不可用时清理器保守失败并记录无敏感诊断。

模型回合、准备步骤和工具结果保存于带版本及摘要的执行日志；完整结果直接复用，
工具原文读取状态一起恢复，问题ID及候选/审查版本保持稳定。
已结算但尚未写入步骤日志的完整响应可按请求摘要重放，不能重复发送。
未完成模型intent仅在新恢复令牌授权下重试，不复用失配的输入、策略、模型或工具契约。

角色循环也接受精确的单工具对象 `call_id/name/arguments`，归一化后仍经过原白名单、
参数和次数检查；不丢弃额外字段或把混合报告内容强行转为工具。
业务运行仅对生成者与审查者开启 JSON 对象响应格式，严格解析整个根对象或完整的
`json` 代码围栏；外层失败不截取内层对象。解析失败清空内容但保留用量结算，
不存储原始思考。专家保持原有解析和思考清洗，不添加 JSON 格式约束。
供应商明确拒绝返回 `model_refusal`，不作为格式错误自动重试。
结构校验发生在角色循环内，失败时给模型有限的字段路径与错误类型反馈，
最多增加两次格式修复调用；仍受共享模型回合、物理请求、token、费用和时长预算约束。
反馈不携带原始输出或思考内容，错误顺序固定，数据库重排JSON键后仍可重放同一请求。
未知完成、费用、资源或权限错误不进入格式修复。

历史版本在首份候选前因已保存的结构片段进入
`needs_review/invalid_review_or_candidate` 时，只对无候选、无未知请求且全部步骤已提交、
摘要完整的生成阶段记录提供 `can_resume_protocol`。原页面复用继续按钮，不新建报告；
恢复仍检查owner、版本、原授权、预算和活动运行约束，不允许重试未知请求，
也不改写原模型结果或摘要。完整候选遭引用或版本校验拒绝、独立审查否决以及
已发布、已取消的终态都不能借此恢复；新循环的格式修复耗尽后也不会再次开放该例外。

检索工具的描述从当前角色的实际业务限制生成，包含查询长度、单次条目数和剩余额度，
不能向模型宣称比执行器更宽的能力。仅 `retrieval_policy_exceeded` 这一执行前参数拒绝
返回无原文的工具反馈，最多允许两轮修正；次数、费用、授权和未知请求仍按原规则停止。
拒绝保留为 `denied`，恢复时不重跑或改写为成功。升级描述时，仅其余上下文完全一致的
旧模型回合复用已冻结的工具说明，避免因为描述变化重发成功请求；存在歧义则拒绝恢复。
历史 `failed/retrieval_policy_exceeded` 仅在唯一首版候选与生成日志、历史摘要绑定，
尚无审查结果、所有步骤已提交或属于该搜索前拒绝且无未知请求时提供显式恢复。
旧结构错误必须出现在完整候选的已保存修复反馈摘要中，不按案例编号放行。
模型原始响应仍按原摘要校验；候选归属使用与生成阶段一致的模型规范化摘要，
允许省略默认空引用列表，不回填事故事实，也不改写原始响应。
此资格沿用 `can_resume_protocol` 字段，不改变 API；原权限、版本和预算校验继续生效。

未知请求默认返回409，只有显式接受重复计费风险且预算充足才允许重试；
旧未知预留继续占用，新请求另行预留，不重置同run预算。发布事务冻结预算快照及
最终事件，后续迟到usage只影响实时账本，不改写历史发布证据。
`backend/tests/test_run_recovery.py`使用真实子进程kill/restart与回环合成HTTP；
该证据不证明真实provider语义、实际费用或报告质量。

## 界面与导出

事故草稿严格保存使用会话 PUT 的可选 `expected_updated_at`（服务端毫秒版本）；
不传字段的旧客户端保持兼容。冲突返回409 `SESSION_VERSION_CONFLICT`，不得自动
刷新重试覆盖。严格保存成功之前不创建报告运行；错误时保留本地编辑。
该事故草稿版本与补证的 `expected_revision` 是两个不同契约，不可混用。

旧报告模式仍为默认；证据报告模式独立查询会话证据与分页运行列表，
不把候选或待审结果写入旧会话的成功报告字段。刷新只读状态，不恢复执行。
证据版本冲突保留本地编辑并返回409；未知请求恢复必须显式确认风险。
切换会话或离开页面会关闭控制流，按取消语义处理。

在线模式的旧 `video_path` 请求先验证用户和会话归属，保留原路径范围校验，
再调用原 `InputGenerationService`。成功生成的事故信息才进入同一报告 harness，
旧响应保留实际 `input_generation`；前置失败不创建报告运行，也不回退旧报告生成服务。
数据库工厂、会话读取/创建或新快照持久化失败时返回503；原有权限与不存在会话错误不改写。
只有报告已发布且具备正式导出资格时，旧接口才保留原 `status="success"`；
运行标识由 `retrieval_meta.report_run_id` 提供，不伪造旧磁盘输出目录。
上游同步视觉调用不因客户端断开而保证取消；报告阶段取消与视觉服务的边界不可混称。
旧报告归属依赖可信服务端 sidecar，或服务端 `run_log.json` 的会话与数据库所有者绑定，
不接受客户端可写的 `report_result` 作为归属证明。新产物写数据库失败返回503，不以新
sidecar 掩盖失败；只有依赖明确返回无数据库对象时保留兼容 sidecar 路径。
数据库已配置时，显式会话不存在或不属于当前账号均返回404；生成期间会话消失也不写新 sidecar。

`GET /api/v1/report-runs`以会话、limit、cursor读取运行列表；candidate是所有者
专用详情入口，不授予发布或下载权限。导出入口为
`/api/v1/report-runs/{run_id}/exports/{format}`，支持md/docx/pdf。
未发布一律拒绝；正式模式每次核对历史批准，撤销立即返回409。
正式旧导出在 DOCX/PDF 渲染后还会复核一次批准，渲染期间发生撤销则不返回生成文件。
`mode=engineering`必须显式选择，文件名和正文强制带工程标记，
Word页眉与PDF每一页也保留标记。渲染使用独立临时目录，结束自动清理。

生产批准表只从`backend/config/report_harness/approved_release_bindings.json`读取，
初始为空，不提供API写入口。加载检查固定路径、schema、重复绑定、
当前进程身份的写权限及父目录替换权限；不会自动改ACL。
普通可写Git工作区不能作为生产批准源，需在获准部署时另行设置只读运行身份。
批准引用的本地JSON验收证据位于同目录`approved_evaluations/{摘要}.json`，
其内容SHA-256和只读权限也必须匹配。

新运行只有在非合成模式、构建清单和四摘要批准绑定都有效时才能冻结质量资格。
正式资格必需的`build_manifest.json`含`version=1`、`clean=true`、`source_hashes`和`code_digest`；
源码清单覆盖后端app、前端src、报告角色模板及依赖清单，运行时重算，
缺失或不一致不赋予正式资格。服务端不生成构建清单或验收证据。
历史运行仍按其冻结绑定核验，不因新代码版本自动改写历史质量状态。
测试只注入只读历史fixture和注册表；合成创建路径始终为engineering_only。

`frontend/tests/harness-e2e.mjs`通过真实浏览器、回环HTTP及独立PostgreSQL验证
保存刷新、证据冲突、取消、未知请求恢复、历史批准撤销及桌面/移动端布局。
生成与审查使用合成角色，不证明实际模型质量或物理计费；相关物理请求预算另由
后端回环transport测试覆盖。正式下载正分支仅用测试注入的历史批准fixture，
下载仍强制工程标记，绝不写入真实批准表。

浏览器入口只用`REPORT_HARNESS_TEST_DSN`，不读取业务`.env`。
API默认端口18081，若被Windows保留则显式设置`HARNESS_TEST_API_PORT=18281`；
前端固定15174，端口被占用立即失败，不接管已有服务。
`REPORT_HARNESS_E2E_OUTPUT`指定本次截图、公开事件和结果目录。
runner退出会关闭自己启动的服务并清理自己创建的数据库行。
真实质量门须另有模型、预算及材料授权；浏览器通过不等于完整E门或Q门通过。

## 隔离真实开发样本

`python -m evals.report_harness.development_run` 仅用于已获授权的本机开发试跑，
不是生产服务器启动命令。参数 `--input` 指向仓外匿名文字JSON，
`--input-sha256` 固定已批准内容，`--experiment-dir` 指定整轮私有账本及产物目录，
`--confirm-outbound` 明确本次允许发出真实请求。输入只支持非空文字字段对象，
不能传原图、DOCX、老师答案或未授权知识。必须显式提供回环测试库
`REPORT_HARNESS_TEST_DSN` 和进程级 `OPENROUTER_API_KEY`，不自动读取业务环境文件。

开发依赖 `development_outbound_enabled` 默认false；打开时必须为outbound、
强制工程导出、具备许可目录和运行时角色工厂，且没有正式发布注册表或代码绑定。
每次请求核对持久approval的所有者、输入、模型端点、知识和策略摘要。
开发运行始终为 `engineering_only`；老师验收与完整Q另行进行，不能自动登记正式批准。

固定报告模型为 `tencent/hy4-preview`，生成与审查独立上下文。供应商和价格有上限，
不自动回退、重定向、重试或调用外部知识/收费插件。运行前核验公开元数据和参考汇率，
按模型完整容量保守预留；未知费用继续占用额度。版本化 `MoneyGuard` 在物理请求层用SQLite
事务执行整轮CNY100限额，跨进程及失败保持累计；请求账本仍只执行token预算，
其尚未实现的 `max_money` 字段保持None，不把未实现字段当货币保护。
试跑前只读核对已登记的生成/审查合同与当前执行证明，摘要写入运行策略和身份记录。
旧输出截断配置的合同不能静默改写或继续使用；先由维护步骤按总摘要及旧角色摘要
显式追加新版本，再运行本CLI。迁移不重算历史金额、不释放未知预留、不增加总额度。

所有案例、重试和恢复必须复用同一 `--experiment-dir` 中的 `money.sqlite3`，
不能另建目录重置额度。报告、源输入、运行轨迹和费用证据留在私有目录，不提交仓库；
缺少正式批准绑定的报告只可作为明确标注的开发稿。输入不足与模型处理错误分别记录。
此开发CLI按同一实验串行执行；有未知费用时默认在新建运行前拒绝，
不能用新session绕过。只有用户明确接受指定请求的重复计费风险后，才可传入
`--acknowledge-unknown-attempts` 及对应整数编号；新出现的未知编号不自动获准，
原未知费用预留也不因此释放。该确认不是增加100元预算。

开发生成协议使用 `QuotedTransportRoles`：模型逐字引用正文中的唯一原句，
适配器将其转换为核心 `CandidateReport` 的 `text_span`，不要求模型计算Unicode字符位置。
找不到原句、重复位置或同时提交字符区间时拒绝；不修改正文、来源或审查结果。
审查者仍读取核心候选及独立证据上下文，发布检查和重放规则不变。
推理配置与传输协议版本进入策略摘要，源码指纹和实际参数随每次私有试跑保存；
失败尝试与费用不得因开发调参而删除，也不把开发调参结果当独立留出结果。

## 离线工程门

在`D:/MCP_Server/TS_analysis_report`执行，DSN仅可指向回环专用测试库：

```powershell
$env:REPORT_HARNESS_TEST_DSN = 'host=127.0.0.1 port=15432 dbname=safetyraise_harness_test user=postgres'
$env:HARNESS_TEST_API_PORT = '18281'
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m evals.report_harness.run --output-dir C:/tmp/internal/think/.mission/20260916_23-14-07-safetyraise-report-evidence/verification/e-next
```

输出目录必须不存在，不能覆盖历史失败证据。runner串行运行完整后端suite、
前端测试、真实子进程清理回归、TypeScript、构建和浏览器；
任何失败、skip或缺少必需浏览器场景都拒绝关闭E。
`manifest.json`列出故障矩阵与旧标签基线；`result.json`保存提交、工作区状态、
命令/退出码/耗时、源码/策略/迁移/构建配置及产物SHA-256。
验证过程中源码变化、旧标签变化或真实批准表变化也判失败。
公开事件通过纯本地`replay_events`重放，不导入服务或网络执行器。
`engineering_gate=passed`仅证明该指纹版本的工程门，`quality_gate`仍为`not_run`，
不写生产批准、不打最终标签、不推送或部署。
测试服务从初始化阶段注册独立清理回调，关闭连接池失败也会尝试删除自身测试行；
浏览器runner从启动时观察进程退出，信号退出不重复等待，强制清理有界。
隔离API需正常退出，否则工程门失败。
